# AUTO — локальна версія Windows

Python **3.12**, Streamlit, SQLModel, SQLite, Alembic. Робоча папка:
`C:\Users\dpetr\Projects\AUTO`. Після встановлення працює без Інтернету.
Сервер прив'язаний лише до `127.0.0.1:8501`.

## Встановлення і запуск

1. Установіть Python 3.12 та Git for Windows. Відкрийте папку AUTO в терміналі.
2. Закрийте запущений AUTO. Виконайте `install.cmd` (потрібен Інтернет).
   Скрипт створює `.venv` через `%LocalAppData%\Programs\Python\Python312\python.exe`
   або `py -3.12`, перевіряє версію та встановлює `requirements.lock`.
3. Запускайте **`start.cmd`**, відкрийте <http://127.0.0.1:8501/>.
   Для зупинки — Ctrl+C у вікні сервера, дочекайтеся завершення.

Активація venv не потрібна. Якщо вікно після помилки закрилося, виконайте
`cmd /c start.cmd` у PowerShell — текст залишиться в терміналі. Порт 8501 має
бути вільним. UI не оновлює схему автоматично; install/update виконують явну
міграцію з backup і відмовляють, поки UI використовує БД.

## Дані та ролі

SQLite: `data\auto.sqlite3`, файли: `data\attachments`. Початково створюються
лише класифікатори. Автомобілі, марки/моделі й персонал додаються користувачем.
Помилковий тип Motoleader ML900ATV виключений за уточненням користувача.
Інша БД задається `AUTO_DB_PATH`; вкладення/копії розташовуються поруч із нею.

Типово роль адміністратора та ім'я Windows. Інший режим задається перед запуском
у тому самому PowerShell:

```powershell
$env:AUTO_USER_ID = 'operator1'
$env:AUTO_ROLE = 'operator'  # admin / operator / viewer
.\start.cmd
```

Персональні фільтри прив'язані до AUTO_USER_ID. Права перевіряються сервісами та
при читанні вкладень. Це конфігурація довіреного локального процесу, а не
парольна авторизація. Права на папку забезпечує Windows. Порт у мережу не відкривати.

## Робота з карткою та Excel

Сім вкладок утримують чернетку в сесії. «Зберегти» записує всі змінені форми
однією транзакцією після перегляду й підтвердження, включно з документами,
обладнанням, примітками, показником і нормою. Помилка скасовує також нові файли.
Власна кнопка форми зберігає лише відповідний запис. «Скасувати зміни» перезавантажує
всю картку; «Скасувати окремі форми» залишає основну чернетку.
Чернетка не переживає закриття браузера/сервера. Гарантованого попередження при
закритті вкладки браузера немає; захищені переходи всередині AUTO.

Датовані зміни потребують фактичної дати, перегляду «було → стане» й підтвердження.
Початкові невідомі дати порожні. Періоди `[від, до)`, майбутні події не змінюють
сьогоднішній стан. При конфлікті версії збережіть потрібний текст окремо,
скасуйте чернетку/перезавантажте запис і повторіть узгоджену зміну.

Норма потребує дати початку, номера/дати наказу й одиниці. Початковий показник
потребує дати та джерела; порожній не стає нулем. Поточний показник береться з
журналу з датою/джерелом/підтвердженням. Див. [контракти](docs/integrations.md).

Колонки, їх порядок і сортування задаються над реєстром. «Як на екрані» повторює
таблицю. Повний експорт потребує вибору вибірки або всіх карток із архівом.
Імпорт: шаблон/свій XLSX → мапінг → перегляд → ручні виправлення/погодження → явне
підтвердження. Активні довідники мають існувати заздалегідь. Формули не
перераховуються; використання кешу окремо погоджується. Наявні картки не оновлюються.
Пропущені рядки є в журналі й XLSX-звіті.

## Резервування й відновлення

Виконайте `backup.cmd`. Консоль покаже перевірену папку `data\backups\<UTC час>`
з SQLite, усіма версіями вкладень та manifest SHA256. Інший диск:
`backup.cmd --destination "D:\AUTO-backups\copy-2026-10-20"` (нова папка).
Копіюйте **всю папку** на інший носій; SQLite без вкладень недостатньо.

```powershell
.\.venv\Scripts\python.exe -m auto.cli verify-backup "D:\AUTO-backups\copy-2026-10-20"
```

Для відновлення закрийте сервер AUTO, виконайте
`restore.cmd "D:\AUTO-backups\copy-2026-10-20"` і введіть **RESTORE**.
До заміни перевіряються checksum, SQLite integrity/FK та вкладення. Поточний стан
зберігається в `data\backups\before-restore-…`. При помилці заміни виконується
відкат. Якщо відкат теж не вдався, файли залишаються за шляхом із помилки:
не запускайте AUTO до відновлення перевіреної копії. Втрату живлення під час
заміни файлів не тестували.

Після відновлення:

```powershell
.\.venv\Scripts\python.exe -m auto.cli check
```

Для копії старої схеми спочатку виконайте `.venv\Scripts\python.exe -m auto.cli migrate`:
створиться backup і послідовно оновиться схема. Старі копії без manifest не
приймаються як перевірений bundle: збережіть оригінал і створіть новий bundle
командою CLI backup із копії SQLite та відповідного дерева вкладень.

## Оновлення

Зробіть `backup.cmd`, закрийте AUTO, запустіть `update.cmd`. Він перевіряє
блокування БД та зміни коду, виконує `git pull --ff-only`, установлення залежностей,
`pip check`, міграції з перевіреним backup. Локальні зміни коду не відкидаються.
Для повернення до старого коду потрібні відповідна версія Git та сумісна БД;
автоматичний downgrade даних не реалізовано. Чисте встановлення й оновлення
пакетів на іншому ПК потребують окремої перевірки.

## Перевірки й обмеження

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pip check
```

Тести використовують синтетичні тимчасові БД. Реальні XLSX, SQLite, вкладення,
резервні копії й секрети виключені з Git; чутливі звіти лише в `.local`.
Повні ПММ/дорожні листи, склад, автогенерація документів та мережевий режим
відкладені. Є захищені інтеграційні знімки, наскрізного сценарію майбутнього
дорожнього листа ще немає. Реальні дані не імпортовані в робочу БД.
