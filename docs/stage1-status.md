Залежності встановлено саме у `.venv` Python 3.12.10 і зафіксовано в lock-файлі.
Перший коміт: `212b97e71ee747949a066148cc8557c6237570e4`; SHA звірено з GitHub main.

## Крок 2

Міграції `0001` (таблиці, FK, CHECK, індекси) та `0002` (СВТ, ЕТС, 13 типів,
рекомендовані одиниці, захист аудиту від UPDATE/DELETE).
Довідники додаються оператором/адміністратором, перейменовуються й деактивуються
адміністратором; нормалізовані дублікати відхиляються, FK захищає використані значення.
Технічні характеристики, точність виготовлення, незалежні стан/категорія,
UUID, порожні ID, версія й автори підтримуються сервісом картки.
Перевірки та запис аудиту виконуються в одній транзакції; SQLite BEGIN IMMEDIATE
серіалізує перевірку дублікатів і запис, version захищає від втрати чужих змін.
Нестандартний VIN потребує пояснення. Погодження винятків поки відкладене:
усі непорожні повтори ID, включно з військовим номером, блокуються.

Перевірено 41 тест: створення мінімальної картки, обов'язкові поля,
невалідні числа/маси/дати, причіп без двигуна, нестандартний VIN,
дублікати всіх ID серед архівних, дві одночасні спроби створення,
атомарність помилки, конфлікт версій, права переглядача, довідники,
фільтри архіву/неповноти, незмінність аудиту та персонал.
Міграції звірено з метаданими SQLModel; повторний запуск не змінює дані.
На тимчасовій версійованій БД перевірено upgrade зі збереженням записів/FK,
створення й читання резервної копії БД та синтетичного вкладення.
Невідома непорожня неверcійована БД блокується. Ruff і git diff --check пройшли.

## Крок 3

Додано Streamlit реєстр із пошуком, фільтрами за всіма основними класифікаторами,
неповнотою, архівом, сортуванням і вибором колонок. Базова картка містить сім
вкладок, явне збереження всієї транзакції, чернетку між вкладками, скасування,
попередження «зберегти/відкинути/залишитися» при внутрішній навігації.
Заголовок показує номер, марку/модель, статус, UUID та версію. Служба не вибрана
за замовчуванням. Тип техніки лише пропонує одиницю, її можна змінити.
Довідники доступні в окремому розділі й через «+» у картці; додавання марки
не скидає інші поля чернетки, вибір моделі узгоджений із маркою.
Історія читає загальний аудит із old/new, автором і timestamp UTC.
Додано базовий довідник персоналу з обов'язковими ім'ям/прізвищем.

UI перевірено Streamlit AppTest: створення/редагування, чернетка між вкладками,
скасування, усі три варіанти виходу, помилка валідації без запису,
архів/пошук/колонки, переглядач, додавання через «+», конфлікт редагування,
додавання довідника, відсутність типової служби/одиниці, старт без БД.
Додатково вручну через браузер на localhost перевірено порожній реєстр,
сім вкладок, індикатор чернетки, збереження введеного тексту при переходах,
попередження перед виходом і відкидання чернетки. У робочу БД тестову картку
не записували. Додано GitHub Actions для Windows/Python 3.12.

Другий коміт: `56f7ddc20e14f5398ffa4ad2ec10ffc642d45c96`; SHA звірено з GitHub main.

Підсумкова локальна перевірка: **53 тести пройшли**, Ruff і `pip check` без помилок.
БД `data/auto.sqlite3`: Alembic `0002`, 0 автомобілів, `integrity_check = ok`,
`foreign_key_check` без порушень. Жодних реальних даних не імпортовано.

## Відкладено за межами етапу

Повні історичні періоди й МВО; конфлікти з дорожніми листами;
погодження повторів, видалення, копіювання картки; документи й вкладення,
обладнання, версії приміток; показники/норми; Excel та персональні фільтри.
Ці функції не заявляються реалізованими. Резервування першого етапу перевіряє
SQLite та копіює дерево вкладень; повна процедура аварійного відновлення
з документами потребує наступного етапу й окремих приймальних тестів.
