# Уточнення попереднього імпортного звіту

20.10.2026 виконано повторний перегляд усіх 42 рядків реєстру та трьох джерел.
Ідентифікатори, докладні зіставлення, звіти й тестові SQLite збережені лише в
`.local`; у робочій БД записів не створено. Робочу SQLite відкривали через
`mode=ro`, `query_only=ON`; контрольна сума до/після однакова.

Попередні **27 кандидатів / 15 пропусків** були результатом технічної валідації
підготовчих пропозицій. Той скрипт підставляв типовий обліковий стан, одиницю
напрацювання й розділяв комбіновані назви. Ці значення не були погодженими
фактами й не повинні означати готовність до реального імпорту.
Після предметного перегляду: **17 попередніх кандидатів, 25 з конкретними
уточненнями**. Усі 42 ще потребують погодження обов'язкових полів/політики
невідомого облікового стану. «Кандидат» не означає «імпорт дозволено».

Суворий повторний пробний імпорт без підстановки невідомих обов'язкових полів
та облікового стану створив **0 карток, пропустив 42**. Це інша політика вхідних
даних, а не регресія кількості допустимих карток. Тимчасово пропоновані значення
довідників відокремлені від вихідного напису; модель/марка не вигадуються.

## 15 попередніх пропусків

11 рядків мають числове подання номера шасі з форматом General. Воно навмисно
потребує ручного підтвердження тексту: наявність або відсутність початкових нулів
не можна довести із такого подання. Захист не вимкнений.
5 рядків мають неоднозначний для цільового довідника опис стану; один із них
водночас має числовий ID, разом це 15 різних рядків. Автоматичного зіставлення
ремонтного опису з «Несправний» не додано.

Підтверджені помилки імпортера виправлені:

- Перша помилка більше не приховує інші: збираються помилки довідників,
  числових ID та валідації полів.
- Текстові ідентифікатори перевіряються на збіги з усією БД/історією та іншими
  рядками навіть тоді, коли інше поле рядка некоректне. Неперевірені числові,
  неоднозначні та формульні ID мають явну причину; порожній список збігів не
  видається за успішну перевірку таких полів.
- Збережені файл/аркуш/рядок та метадані клітинок, показані застосовані типові
  значення. Параметр `required_explicit` дозволяє вимагати явні значення заданих
  полів без використання типового як факту. Політика входить у підпис перегляду
  та повторно перевіряється при застосуванні.

Непогоджені словники, неоднозначні номери, відсутні дати/одержувач/показники
не виправляються автоматично. «ВИБУЛА» означає «Передано»; дата й одержувач
залишені невідомими. Координат у нових звітах немає.

Перевірено також обидва аркуші контролю ТО, які не брали участі в попередньому
зіставленні. Повтори у календарних/ТО-таблицях не оголошені новими автомобілями.
Візуальні/коментовані ID — лише питання до користувача; жодного злиття немає.

Перевірки: `tests/test_import_diagnostics.py` — накопичення помилок, збіги
відхилених рядків, явні поля, походження, непідтверджене числове подання.
Повний прогін: **159 тестів пройшли**, Ruff і pip check успішні.
Перед реальним імпортом потрібні відповіді користувача, новий підсумковий
перегляд, звірка актуальної БД та перевірений backup SQLite разом із вкладеннями.
