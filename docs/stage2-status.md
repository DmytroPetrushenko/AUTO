# Другий етап

## Схема та міграція

Міграція `0004` додає версії персоналу, нормалізований особистий номер,
МВО автомобіля, типізовані періоди `vehicle_history`, погодження дублікатів
і незмінні знімки застосованих зовнішніх документів.
Єдина таблиця періодів розрізняє підрозділ, службу, МВО, стан/статус/експлуатацію
та чотири ідентифікатори. Посилання на довідники захищено FK.
Інтервали напіввідкриті `[valid_from, valid_to)`; NULL початку означає невідому
фактичну дату. Початкова історія міграції не використовує дати created_at,
accounting_date або сьогодні замість невідомої дати.

Перед міграцією перевіряються дублікати особистих номерів: неоднозначні дані
блокують оновлення без автоматичного злиття. Таблиці vehicles/personnel
розширюються без видалення таблиць або вимикання foreign_keys.
Копія SQLite перевіряється integrity_check і foreign_key_check;
дерево локальних вкладень також копіюється, якщо є.

Перевірено заповнену синтетичну БД версії 0003, її окрему тестову копію,
збереження кількості автомобілів, персоналу, ID та зовнішніх зв'язків,
невідомих дат і відмову при дубльованих особистих номерах.
Після перевірки копії локальної БД зроблено перевірений backup та виконано
локальну міграцію до 0004. Excel і реальні дані не імпортувалися.

## Наступні кроки цього етапу

Бізнес-операції періодів із переглядом і підтвердженням, повні погодження
дублікатів, права персоналу/МВО та захист застосованих документів; далі UI
та сценарні тести. Повний модуль дорожніх листів не створюється.
